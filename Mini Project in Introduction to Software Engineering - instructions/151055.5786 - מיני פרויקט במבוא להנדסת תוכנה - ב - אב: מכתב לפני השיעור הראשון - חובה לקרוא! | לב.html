מכתב לפני השיעור הראשון - חובה לקרוא!

דרישות השלמת קורס
שלום וברכה לכולם,

כמעט מיד אחרי פורים (ביום ראשון בשבוע הבא) מתחיל סמסטר ב'. כפי שכבר ידוע לכם – בעקבות פתיחת המלחמה "שאגת הארי" הסמסטר הוקדם בכמה ימים.
אנא קראו את המכתב במלואו (למרות שהוא מעט ארוך). במכתב זה מופיעות הנחיות שעליכם לבצע עוד טרם השיעור הראשון. אנא קראו בתשומת לב ועד הסוף.

מספר דברים שחובה לעשותם לפני השיעור הראשון: (לכל הסטודנטים שלא נמצאים במילואים לפני\בתחילת הסמסטר):
  • נ.ב. ניתן לעבוד בכל סוג מחשב נייד אישי של הסטודנט: חלונות, לינוקס, מאק. העיקר שחומרת המחשב תהיה מספיק חזקה (רצוי 16GB זיכרון נדיף – RAM, אך לפחות 8GB זה חובה)
  • חובה לבצע את ההתקנות של Java JDK, תוכנת ניהול גרסאות Git ושתי סביבות הפיתוח – לפני השיעור הראשון
    • הנחיות התקנה נמצאות באתר הקורס
    • סדר ההתקנה: תחילה Java JDK, לאחר מכן Git (למי שלא התקין בסמסטר א'), ורק לאחר מכן סביבות הפיתוח
    • כלי פיתוח של Java – תוכנת Java JDK – חייבת להיות  מותקנת לפני התקנת סביבת הפיתוח
      • חובה להתקין גרסה 25 של JDK – זוהי גרסת LTS (תמיכה לטווח ארוך), כאשר גרסאות 26-27 (גישה מוקדמת) הן גרסאות ניסוי ללא תמיכה לטווח ארוך (ראו פרטים בקישור https://www.oracle.com/il-en/java/technologies/java-se-support-roadmap.html)
      • שימו לב שבמחשבי מעבדות המרכז האקדמי הותקנה גרסה 21 מכיוון שבזמן ההתקנות טרם שוחררה גרסה 25 
      • אם יש לכם התקנות ישנות של JDK – מומלץ לעשות uninstall לכל הגרסאות הישנות למעט גרסה 8 (שמוכרת גם כגרסה 1.8), אלא אם יש לכם תוכנות שזקוקות לגרסאות ישנות של Java
    • אנו ממליצים להתקין את שתי סביבות הפיתוח – Eclipse ו-IntelliJ IDEA
      • הנחיות התקנה של IntelliJ IDEA – בתיקיה נפרדת באתר הקורס (באדיבות מר אליעזר גנסבורגר)
      • תתייעצו עם חברים לגבי סביבת הפיתוח המועדפת
      • דעו שמרצים שונים מעדיפים סביבות פיתוח שונות – אז תשאלו את המרצה שלכם מה הוא מעדיף ולמה
      • אינכם חייבים להשתמש בסביבה המועדפת על המרצה שלכם, אך כדאי מאוד ששני השותפים לזוג ישתמשו באותה סביבת פיתוח ובאותה גרסה (אפשר גם להשתמש בסביבות שונות, אז זה ייצור לא מעט אתגרים מיותרים)
      • כרכז הקורס ובעל ניסיון עבודה ופיתוח בסביבת זמן אמת עם ריבוי תהליכונים (multi-threading) – אני אישית ממליץ להשתמש ב-Eclipse למרות שחלק מהמרצים אוהבים יותר את IntelliJ IDEA
      • מאוד לא מומלץ לעבוד עם VSCode (למי שעולה רעיון כזה בראש)!
  • חובה להאזין להקלטת השיעור ב-Java של הרכז או של המרצה שלכם לפני השיעור הראשון (ניתן ללמוד על Java ועל סביבת הפיתוח המתאימה גם ממקורות אחרים לפי בחירתכם)
  • חובה לבצע את תרגיל 0 לפני השיעור הראשון (התרגיל ללא ציון ומהווה תרגול ראשוני ב-Java ובשימוש בסביבת הפיתוח)
    • חובה להציג את תרגיל 0 למרצה בשיעור הראשון
    • עבודה על תרגיל 0 מתבצעת לבד בלבד – כל סטודנט עושה את התרגיל לחוד (אסור לבצע את התרגיל בזוגות!)
    • חובה להקפיד על מוסכמות שמות, דרישות עיצוב, ותיעוד JavaDoc – כבר בתרגיל 0!
    • אי הצגה של תרגיל 0 בשיעור הראשון (ללא עילה מוצדקת כפי מוגדר בתקנון הלימודים) תמנע את המשך ההשתתפות של הסטודנט בקורס
לגבי המשך הקורס משלב 1 ועד סוף הפרויקט:
  • עבודה בקורס מתבצעת בזוגות בלבד (אותו זוג מהתחלה ועד הסוף)
  • שני השותפים לזוג חייבים להיות רשומים באותה קבוצה
  • כבר בשיעור הראשון תתחלקו לזוגות ותתחילו לעבוד על השלב הראשון של הפרויקט (במקביל להצגות של תרגיל 0 המקדים)
  • נשתדל מאוד שציוני מועד ב' של הקורס "מבוא להנדסת תכנה" (קורס קדם למיניפרויקט) של סמסטר א' יגיעו בהקדם (לאחר שיתקיים מועד ב'), יחד עם זאת לא כולם מצליחים לעבור את קורס הקדם
  • חובה שהעבודה תתבצע ע"י השותפים לזוג בשיטת תכנות זוגות – Pair Programming (להבדיל מחלוקת עבודה בין השותפים לזוג) שלמדתם בקורס התאורטי, אך אפרט בקצרה – תמיד שני השותפים עובדים ביחד, אחד על המקלדת והשני צופה, מאיר ומעיר, ומתחלפים מדי פעם, כך שכל אחד יהיה כמחצית מהזמן על המקלדת
  • חובה לחבר את הפרויקט שלכם למאגר Git מקומי שיחובר גם למאגר Git משותף (ע"י אחד מהשותפים לזוג) באתר github.org – ראו בהנחיות
  • כל השיעורים יתבצעו ללא לימוד פרונטלי למעט מקרים חריגים. בכל שיעור עליכם להציג למרצה שלכם את השלב האחרון שהשלמתם (הגנה). המרצה יתן לכם הערות על הקוד שלכם – עליכם לבצע תיקונים על פי ההערות לפני שאתם ממשיכים הלאה (אחרי ההגנה). ההערות שלא תוקנו יגרמו להורדת ציון חוזרת ומשמעותית בשלב הבא. זוג שטרם הציג את השלב הקודם אינו ממתין – אלא ממשיך לעבוד על הפרויקט (על השלב הבא בדרך כלל).
העבודה על כל שלב:
  1. סדר העבודה תמיד: קודם כל – קריאת מצגת
  2. לאחר מכן התחלת העבודה על השלב תוך קריאת ההנחיות (המופיעות בקובץ שבתוך תיבת הגשה)
  3. שימו לב: תיבת הגשה כוללת גם חומרים נוספים לכל שלב – בדרך כלל מודולים של פרויקט, שאתם מקבלים מוכנים לשימוש
  4. בהגנה, המרצה יזהה בדרך כלל האם העתקתם קוד משנים קודמות ו-\או לא עקבתם אחר ההנחיות – כתוצאה מכך עלול להיפגע ציונכם
  5. אנחנו מעודדים שימוש בכלי בינה מלאכותית (AI) במהלך העבודה, אך האחריות על הקוד היא שלכם בלבד – כולל התאמה סגנונית ועיצובית, והיכרות מלאה עם הפונקציונליות
  6. בהגנה תידרשו להסביר את מה שאתם מציגים. הקראת הקוד אינה הצגת פונקציונליות. טיעונים כגון "כתבנו את זה מזמן" או "לא זוכר" יובילו להורדת ציון
  7. חובה להקפיד על הדרישות בהנחיות, על סגנון ומוסכמות כתיבת הקוד כנדרש, תיעוד javadoc, וכדומה. מעקפים וקיצורי דרך יפגעו בציונכם
בפרויקט יש 10 שלבים אם דרישות חובה (עם משקלים שונים בציון הכללי), בחלקם בנוסף יש אפשרויות פיתוח נוספות (כמוגדר במצגות ובהנחיות) המאפשרות לצבור נקודות נוספות לציון הכללי. מטרת התוספות הן לכסות את הנקודות שאולי תאבדנה בשלבים. אך גם בלי התוספות, ציונכם יכול להגיע לציון 100.
